## 目的

デルタもん歌唱modelのローカルRVC学習で得た、長時間process、外部asset、段階成果物、
失敗伝播、火力不足の扱いを、ZeroRoomLabの横断運用へ戻す。RVCコード、voice model、
学習音声、生成音声をManifestの正本へ取り込む提案ではない。

## [FACT] 観測した実験

- source音声65 files / 805.442 secondsをAirDriveからsymlinkで参照し、source本体をrepositoryへコピーしなかった。
- RVCの前処理233 clips、F0 233/233、HuBERT 233/233を段階別に完了した。
- 無音1 fileは`UnboundLocalError`を起こしたが、skipと理由を記録する修正後に再実行できた。
- Python 3.12ではscript path直接起動がimport root衝突を起こし、`python -m ...`で回避した。
- GPUなしで不要なDDP TCPStore bind、CPU DataLoader workerの`torch_shm_manager`が失敗した。
- CPU single-process / worker 0へ切り替えた後、model底重みをロードし、epoch 1、epoch 2まで到達した。
- 前景TerminalのAppKit `EXC_BAD_ACCESS/SIGSEGV`はPython学習processとは別主体だった。
- GitHub Issue #10〜#13を障害・修正境界として記録し、#11〜#13は修正実測後にcloseした。

## [INTERPRETATION] Manifestへ返せる運用知見

### 1. Resource / Supply / Exit（#4）

計算火力不足やreset待ちは、目的失敗ではなく`RESOURCE-WAIT`または`RETRYABLE`として扱える。
source、model、cache、生成物は供給経路と権限が異なるため、単一の「asset available」へ潰さない。
長時間作業では、foreground hostの終了とtaskの終了を同一視しない。

### 2. Field -> Fold / failure trace（#13）

「学習中に落ちた」は単一原因ではなかった。少なくとも次を別eventとして保持できる。

```text
Terminal/AppKit crash
Python entrypoint import collision
silent-clip preprocessing bug
CPU DDP socket restriction
CPU DataLoader shared-memory restriction
```

主体、host、stage、exit code、artifact stateを分離しないと、Terminal crashをmodel破損、
partial failureをsuccess、未開始epochを途中成果と誤認する。#13のFold traceでは、
`L=host/infrastructure`, `S=preprocess|feature|train`, `result=failed|retryable|running`を
候補として保持し、座標名は既存正本との照合前はDraftとする。

### 3. Task / receipt schema（#25）

最小receipt候補は次の通り。これはschema採用ではなく、validator設計へ渡す観測例である。

```yaml
task_id: deltamon_singing_40k_v2_20260901
source_ref: external-local-airdrive
host: managed-python-process
stage: preprocess | f0 | hubert | train | index
state: READY | RUNNING | REVIEW | DONE | FAILED | RETRYABLE | HUMAN_REQUIRED
artifact_refs:
  - ignored-local-log
  - external-model
  - external-audio
observed_exit_code: 0 | 1 | unknown
completion_claim: stage-local-only
unknown:
  - final quality
  - publication authority
```

`Issue close`、`project status`、`stage success`、`model quality`、`public release`は別fieldであり、
一つのDONEへ折り畳まない。

### 4. Local salvage / provenance（#19）

sourceと生成物は「見つかった」だけで公開可能にならない。今回もAirDriveの音声、RVC base
weights、学習中間物、最終modelを別保管し、repositoryには実験票と相対参照だけを置いた。
権利確認中のデルタもんmodelの公開・再配布・upstream先は`unknown / HUMAN_REQUIRED`のまま残す。
