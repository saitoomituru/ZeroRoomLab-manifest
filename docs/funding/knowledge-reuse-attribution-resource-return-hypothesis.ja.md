# 技術知識の再利用と評価・研究資源の還流ギャップ：独立R&Dの検証仮説

- Status: `WORKING HYPOTHESIS / FIELD OBSERVATION / NOT CAUSALLY ESTABLISHED`
- 記録日: 2026-10-31
- 正本の調査Issue: [ZeroRoomLab-manifest #60](https://github.com/saitoomituru/ZeroRoomLab-manifest/issues/60)
- 関連: [#58 OSS関心から貢献・寄付への変換](https://github.com/saitoomituru/ZeroRoomLab-manifest/issues/58)、[#26 公式名前空間の財布ペイン](https://github.com/saitoomituru/ZeroRoomLab-manifest/issues/26)、[#52 実機と研究用電力](https://github.com/saitoomituru/ZeroRoomLab-manifest/issues/52)

## 1. 問題の定義

**公開した技術観測や抽象構造が第三者の技術的生産に再利用されることと、その研究を生み出した個人・ラボが継続して探索できる資源を受け取ることは、異なる事象である。**

OSS・研究コモンズでは、第三者による引用、追試、記事化、設計への取り込みが起き得る。これは技術的な外部有用性の観測であり得るが、それだけで研究者個人の認知、研究室の設備、電力、開発時間、次の実験への資本にはならない。

ここでは便宜上、次の非同一性を置く。

```text
Knowledge reuse            != Attribution to original observation
Attribution                 != Recognition of researcher/lab
Recognition                 != Material or labor support
Source availability         != Product distribution
Product distribution        != Research resource return
No visible return           != No private recognition / no future return
```

このモデルは観測量を分類するための工学的・経済的な仮説であり、普遍法則、経済学上の因果効果、個別第三者の義務を証明したものではない。

## 2. 2026-10-31時点の具体例

### 外部技術記事への観測伝播

- 2026-10-26の外部記事：[John Cook, *How to Make Claude Code Use Your Skills Automatically*](https://youcanbuildthings.com/articles/claude-skill-not-triggering/)。
- 記事はXの `@K_chachamaru` によるClaude Code Skillsの未起動観測を明示的に引用・紹介している。Skillファイルを読み、resolverが動くと分かっていても、実際のSkill起動経路を通らず手動模倣したという問題である。
- 記事筆者自身は別の構成で18回のSkill起動実験を実施し、独自の実験結果・解説を追加している。記事の全知見が元投稿から派生したという意味ではない。
- 当該記事で出典人物の表示は存在する。**「無断盗用」や「クレジットを削除された」との主張ではない。** むしろ出典表示があっても、その先の属人的評価や研究資源への変換は独立の課題として残る、という観測である。
- 同系統の開発現場事故（通称「フルチンClaude」）の全因果が当該記事に検証・記載されているわけではない。Skill未起動という故障モードの共有と、ローカルのManifest/FAM/MAGI統合事故を混同しない。

### 観測範囲の限界

外部の記事で技術的な着眼点が扱われた事実は確認できる。一方、記事を読んだ人が誰か、元投稿からどのリポジトリへ到達したか、スター、スポンサー、貸与、共同研究へ何件つながったか、技術知識がどの実装に導入されたかは別途測定が必要である。観測不能な非公開評価を「存在しない」と宣言しない。

## 3. 分断が生じ得る段階と仮説

```text
一次観測・事故票・理論・OSS
  -> 外部での引用・要約・技術実験
  -> 発見者の帰属を認識
  -> 発見者の研究全体を把握
  -> 配布物を試す／追試する
  -> 支援意思と支援手段・予算権限が一致
  -> 電力・計算資源・現物・人手・資金が研究所へ戻る
  -> 次の未解決問題を実験する
```

**H1 抽象度／配布成熟度ギャップ**：技術的な負例、設計概念、仕様案、ソースコードは専門家が記事・研究に組み込みやすい。一方、一般ユーザーが入手して即使える配布物は未成熟な場合があり、公開知識の伝播が製品採用や支援に先行する。

**H2 出典表記／属人評価ギャップ**：一次観測へのリンクやアカウントの記載があっても、それが開発者本人の研究所・継続中の研究・資源需要の理解に自動で連結するとは限らない。適切な引用があることと継続的な支持を得ることは別である。

**H3 受益者／予算保有者分断**：技術的な問題を理解する人、記事や実装で知識を利用する人、寄付や設備貸与を決められる組織の担当者は一致しない。

**H4 ディストリビューション／説明コスト**：プロダクトの価値が抽象的・多層的な場合、説明・ビルド・環境構築・検証・導入のコストが増える。完成したインストーラーがないために価値がゼロになるわけではないが、入口の障壁は評価・普及を抑える可能性がある。

**H5 任意還流／非独占コモンズ**：ライセンスに従う再利用や引用は、それ自体で寄付や購買を要求しない。無償利用を敵視するのではなく、独占権を売らずに研究継続を支える経路を設計する必要がある。

**H6 時間差・計測死角・決済摩擦**：支援や影響が遅れて現れる、非公開経路で起こる、別名義で発生する、あるいは決済・組織手続で離脱する可能性がある。最後の点は[#58](https://github.com/saitoomituru/ZeroRoomLab-manifest/issues/58)で別途調べる。

これらは競合・併存し得る。特定の一仮説を、少数事例から一般化しない。

## 4. テストできる条件

### 観測レジスタ例

| ステージ | 計測候補 | 不明値の扱い |
|---|---|---|
| 一次観測 | 原投稿・Issue・commit、日時、source revision | 原典未特定ならUNKNOWN |
| 外部再利用 | 引用URL、掲載日、どの主張を扱ったか、追試有無 | 直接の派生関係は未確認ならUNKNOWN |
| 帰属 | 原投稿リンク、GitHub/研究者への導線の存在 | 著者を推定しない |
| ディストリビューション | source-only、buildable、demo、installable、operable | 各成果物・対象OSごとに別判定 |
| 評価 | Star、Follow、Issue、PR、記事、レビュー、協力申し出 | 全媒体を合算して「人数」にしない |
| 研究資源 | 電力kWh・稼働可能時間、計算時間、貸与ボード、費用、支援労働 | 非公開・未測定をゼロにしない |
| 継続可能性 | 稼働branch、再開できた実験、停止中の装置 | 文章更新を実機復旧と混同しない |

### 最小比較実験

1. 一つの技術的観測を、**一次事故票／短い再現手順／実際に起動できる小さなデモ／配布可能なアーティファクト** の複数入口で示す。未実装の段階は未実装と表示する。
2. 入口ごとに原典への参照、開発者／研究所紹介、最新の不足資源、資金以外の追試・機材貸与・レビュー導線を同程度の見つけやすさで置く。
3. 観測期間、露出、対象言語、媒体、入口の完成度を記録。コンバージョン件数だけでなく、元記事からのsource到達や技術的質疑も追跡する。
4. 差が出ない／未成熟な配布でも支援が生まれる／引用が全くなくても支援が生まれる事例を反証として保管する。
5. 第三者の個人情報や支払い情報を収集・公開せず、可能な集計で比較する。サンプル不足は結論保留とする。

**成功指標は「Star数」単独ではなく、一次観測が追試され、研究者へ適切に帰属し、次の実験が実施可能になったかを分けて扱うこと。** 間違い・失敗・不成立条件の発見も研究成果に含む。

## 5. 改善候補

### A. 出典カードの追加（低コスト）

外部技術者が一次資料を紹介するときに添えられる小さな入口を用意する。

```text
Observation: 何を観測したか / claimの射程
Source: 一次投稿・Issue・revision
Reproduction: 追試方法、実行可否
Research context: どの開発群・仮説に属するか
Current constraints: 今、何の資源が不足しているか
Contribute: 負例、PR、ボード貸与、実験電力、研究費など
```

これを要求義務ではなく任意利用できる公開情報とする。第三者が簡潔に正確な紹介を作るコストを下げる。

### B. 配布成熟度と研究成熟度を別軸化

`IDEA / PROTOTYPE / SOURCE-AVAILABLE / BUILD-VERIFIED / DEMO-RUNNABLE / DISTRIBUTED / FIELD-VERIFIED` を製品・環境別に記録する。技術的な独創性・研究上の発見を、配布段階の遅れで無価値化しない。逆に研究上の仮説を量産済みと誤表示しない。

### C. 資源投入の入口を複線化

金銭以外にも、計算ホスト、アクセラレータ、電力、工作・測定設備、現物、ビルド追試、技術レビュー、他言語化、記事紹介が研究を進め得る。研究基盤の必要条件を可視化し、一人の大口支援者や一社の独占契約に依存させない。

[Non-Exclusive Seed Steward](non-exclusive-seed-steward.ja.md) の非独占・非支配原則を維持する。支援の対価として科学的結論、設計権限、宗教・文化表現、OSS利用権を渡さない。

## 6. 問題の主張射程

この文書は「引用すれば金を払え」でも「技術者が不当に奪っている」という告発でもない。観測事実は**知識が移動した**こと。未解決問題は**その移動が、研究継続の資源形成と必ずしも結びついていないこと**。

コモンズを壊さずにこの非対称性を縮めるには、技術・配布・帰属・資源調達を独立の設計対象として扱い、同じ指標へ潰さず反証可能な条件を作る必要がある。
