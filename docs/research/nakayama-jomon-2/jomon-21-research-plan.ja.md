## 2. 都市工学として何を問うか

研究質問：

> 目標・所属・知識・土地・設備・供給・運営責務を一組織へ束ねる構造と比較し、独立目標を持つ複数Foldを接続する構造は、地域の研究生産能力への参入・再利用・復旧・探索範囲をどう変えるか。効果が消える条件と追加調整費用は何か。

都市・集落・地域の工学に接続する観測対象は、場所に固定された設備・電力・水・物流・技能と、その利用権限、情報流通、実行能力の分布である。ソフトウェアだけのgraph試験から都市全体の持続可能性を証明しない。土地、季節、輸送距離、設備保守、地域内外の依存、文化活動を含む実行条件を記録する。

知識公開は物理的再現性と同義ではない。例えば雪冷却の設計は移送できても、積雪・気温・熱負荷・保守条件は地域ごとに異なる。相手地域での同一性能を要求するのか、別方式で同じ機能を達成すればよいのか、実験前に定義する。

## 3.1 追加仮説：リスク吸収基盤が成立している範囲と組織学習の射程

2026-11-02、著者より追加：仲山型の成長・チーム形成が成立しやすいのは、既存事業の資金・信用・責務・販売経路等が事業リスクを十分に引き受け、残る制約が協働・学習・役割形成にある場合ではないか。リスク吸収基盤自体が不足する主体には、組織内のチーム化だけでは届かない問題が残る。

これは「仲山モデルは特定業種・大企業にしか有効でない」と確定する主張ではなく、適用条件と限界の追加仮説H9。チーム形成に効果があることと、事業の継続・投資・探索が可能になることを別の従属変数として測る。

著者が挙げた探索対象は、建築、AI・ソフトウェア、芸術、風営、農業、インフラ、および医療関連テールリスク・スティグマ摩擦を持つ活動。業種を一律ハイボラリティと分類せず、案件・主体・地域ごとのリスク構造を調べる。小売・飲食・メーカーにも基盤不足や需要急変はあり、大企業にも相関した尾部損失はあるため、規模・業種を成立条件の代理にしない。

リスクプーリング（損失を複数主体・事象へ分散）、損失吸収余力、流動性、投資可能な資金、責務境界、市場アクセス、成果の価値を回収する交渉力は別軸である。相関した災害・価格変動や深い不確実性は、主体を増やすだけで分散できるとは限らない。

| 調べる障害 | チーム化だけで解消するかという問い | 必要な証拠 |
| --- | --- | --- |
| 下請け固定・取引依存 | 社内の生産性向上が、その主体の余力や自主性へ還元されるか | 価格転嫁、支払条件、発注集中、変更負担、知財・顧客アクセス |
| 豊作貧乏型の価格反応 | 生産成果の増加が収入・維持資源の減少を招く条件はあるか | 収量・品質・価格・需要・保管・販路・費用の時系列 |
| 長期・極端・不確定な損失 | 固定チームが探索を続けられる範囲はどこか | 損失の相関、支払時期、予備資源、資金調達、保険・契約等の実態 |
| 医療負担・スティグマ摩擦 | 個人の技能・協働とは独立した参加・継続障壁が残るか | 本人同意下の負担記録、サービス・決済・場所へのアクセス、公開制度資料 |
| 価値回収と探索の閉塞 | 技術成果があっても研究資源へ還流しないか | 利用・引用と資金・設備・人時の還流を別々に追跡（#60） |

H9：リスク吸収基盤が十分な条件では仲山型のチーム化が成長・学習へ寄与する一方、基盤不足条件ではチーム内指標が改善しても継続・探索は制約される。縄文2.1はこの不足へ、知識共有、設備・専門家への接続、責務分割、継続資源を供給できるかを検証する。

競合仮説：仲山型の協働・顧客との関係づくり自体が、新たな販売経路・資源・リスク分担を生み、基盤不足を改善する場合もある。公開原文と実例を調べ、当方の差分を過大化しない。逆に2.1でもコモンズや創業者に損失が集中する場合、H9の解決策としての主張を縮小する。

机上比較はA〜Dの構造条件に加え、次の環境条件を交差させる。

| 環境条件 | 基盤に余裕がある | 基盤が不足する |
| --- | --- | --- |
| 成果の価値を主体が回収しやすい | 組織学習による成長を観察 | 継続資源の制約と接続効果を観察 |
| 成果の増加が余力へ還流しにくい | 生産性と価値回収の乖離を観察 | 下請け固定・価格反応・負担集中の複合条件を観察 |

資金・人員・設備の総量を揃えた構造比較と、追加資源投入の効果は分ける。2.1側だけに資源を増やして優越を主張しない。一方、資源接続能力そのものを測る実験では、同じ接続機会から実際に使える資源へ到達した過程を結果として記録する。

## 3.2 追加修正：利益の変動と社会的テールを分け、自動化を組み込む

2026-11-02、著者はH9の背景を補足した。著者の「弥生型」は、低変動の産業の単なる古い管理方式ではなく、高い不確実性や資源不足の下で、統治・集約・計画によって限られた資源を配分する構造として読む。これは本研究の機能的仮説であり、歴史上の弥生社会の成立原因を実証した記述ではない。

したがって「既存産業は手堅く、ボラティリティが枯れているから仲山型が成立する」という一律の説明は採らない。企業の利幅・価格変動、事業体が負う損失、社会全体の供給途絶・不可逆被害は別の分布である。市場価格が安定していても、社会的な尾部損失が小さいとは限らない。

著者が挙げる例は、AIのtoken単価、農業の米価格のように上振れの回収が価格競争等に制約される一方、下振れに大規模security incident、食料不足・飢餓等を持つ可能性のある構造。電力・工事も、提供主体の小さい利幅と重大な社会的影響が同居し得る比較対象とする。これらは機序・事例を検証する対象であり、業界全体の統計的分布や個々の事故因果を確定したものではない。

仮説H10：

> 利益として回収可能な上振れと、供給・安全が破綻した場合の下振れが非対称な活動に自動化を導入するとき、単一主体への集中調整と、複数Foldによる資源・知識・実行・復旧の分担では、便益の回収、損失の伝播、探索・復旧能力が異なる。

縄文2.1は統治機能を消すだけの提案ではない。従来の集約が担っていた資源配分、全体調整、保守、供給継続、異常検知、緊急時の判断を、どのFoldとinterfaceが担うかを明記する。自動化は背景説明だけでなく比較条件へ組み込む。

| 分離する量 | 観測・設計すること |
| --- | --- |
| 局所の便益・利益 | 単価、余剰、費用節約、研究・維持資源への還流。価値を金額一つへ統合しない |
| 局所の損失 | 設備停止、手戻り、現金・人時の消耗、保守負荷、責務 |
| 社会的な下振れ | 供給途絶の範囲・時間、危害経路、不可逆性、周辺主体への伝播。賠償額を危害の代理にしない |
| 自動化の条件 | 対象作業、残る人間のrole、検知・停止・復旧権限、必要技能、失敗速度と規模 |
| 共通原因・相関 | 同一model、更新、cloud、設備、供給者、認証基盤への共通依存 |
| 分散側の追加負担 | interface管理、連絡遅延、責務空白、調整人員、コモンズ維持費 |

同じ総資源と同程度の自動化能力を持つ集中条件／複数Fold条件を比較し、自動化の度合いも別に変える。自動化で単純に人が不要になるとは仮定せず、監督・保守・例外処理への人時移動を測る。

机上fixture候補：自動化された共通componentの不良更新、設備提供者の離脱、価格低下と需要増、地域資源の不足、共通供給者の停止。一つの局所判断が他Foldへどう伝播し、誰が何を観測・停止・代替・回復できるかを追う。人身被害を実験的に発生させず、机上・simulation・封じ込めた機能試験で評価する。

相関した自動化故障を2.1がかえって拡散する、調整遅延が増す、または集中方式が同資源で優れる場合は重要な反例。N対NやOSS/OSHであること自体を安全性・risk poolingの成立証明にはしない。

外部調査には、価格・利益の資料と別に、事故調査報告、供給途絶・復旧記録、自動化の共通原因故障、産業別の保守・資源配分の実態を追加する。価格だけからtailを推定しない。

## 3.3 比較の主旨の確定と2.5への移行条件案

著者の補足：仲山型を否定するのでなく、既存の営利商業組織と両立する人間の協働・成長モデルとして読み、その公開説明だけでは扱い切れていない可能性のある射程を当方が提示する。雇用・金銭面を中心とする事業上の危機と、供給・設備・安全等の物理破局および自動化された実行の継続を区別する。どちらのモデルも両領域で無効・万能とは断定しない。

縄文2.1の重点は、社会に必要な供給であるにもかかわらず、価格・利益としての回収可能性と維持・安全・探索に要る負担が釣り合わず、営利単位だけでは維持が難しくなる条件。コモンズ・ファンデーション・商業等の複数Foldを接続し、営利の限界が供給全体の破局へ直結しない構成を研究する。人間のチーム運営には仲山型を併用可能とし、当方への階層的従属を要求しない。

これは仲山モデルへの射程外・補完仮説。本人原文に既に対応する資源・責務・物理継続の契約があれば差分を修正する。商業が失敗する全条件で2.1が解決するという主張にはしない。

著者が提示した2.5移行条件を、次の工学的な到達目標として追加する。

> 自動化・供給系のマイクロ化によって、最先端科学文明を維持するための最小人数が、顔の見える信用関係で運営可能な共同体の人数より小さくなること。

発言中の「ダイバー数」は文脈上ダンバー数を指す可能性があるが、用語は本人確認待ち。特定の人数を普遍定数や達成済みの閾値として採用しない。「最小人数＜顔の見える信用圏」は人数・役割・期間・技能・交代要員・地域条件・外部依存が定義された場合の研究上の判定候補である。

以前の「約300人」は構想上の初期目標として保持する。地域全体の人口、直接協働する人数、各祠／Foldの管理人数、供給圏の人数は異なり得るため、300人と信用圏の大小関係を勝手に同一視しない。

移行判定の検討項目：
- 最先端科学の対象能力と、生活・芸能・お色気・文化・信仰等を含む維持service集合
- 人数に数える常駐者、外部専門家、保守・交代・教育・ケア・緊急対応人員
- 初回deployment、定常維持、設備更新・再製作、障害復旧に要る人数と人時
- 外部電力・材料・半導体・物流・知識更新への依存。遠隔労務を人数外へ隠さない
- 全員が全員を知ることを要求するのか、各祠の信用圏を連接できればよいのか
- 顔の見える信用と、独立した異論・退出・参加・資源利用が両立するか
- 自動化が停止・誤動作した場合にも、必要な能力と文化生活を維持・回復できるか

これは2.1を完成と宣言する条件ではなく、2.5ロードマップを工学指標へ落とす候補。顔の見える関係があるだけで安全性・非支配・高信頼性が自動成立するとはしない。

## 3.4 主題の再配置：共同保障・世代間維持を要する供給系のコモンズ枯渇

主論文は仲山モデルへの評価そのものから、「商業的合理性と供給継続が乖離する条件に対する都市工学のパイロット仮説」へ重心を移す。仲山モデルの原文比較は関連研究・補助文書として保持し、反証探索を継続する。

対象は、単独の事業者・地域・年度では吸収しにくい損失の規模・相関・時間軸と、設備・技能・知識・文化等の維持更新を持つ活動。業界団体、公的再保険、共済、共同保守、ユニバーサルサービス、長期資本等を要する理由を比較する。これらは全て同一の「再保険」ではなく、損失補償、平時の維持費、災害時の現物供給、人材育成を機能別に区別する。

著者が挙げる農業・電力・通信・設備・ソフトウェア・AI・建築は調査対象群。業種全体が必ず市場で失敗するという分類にはしない。個々の取引で合理的な撤退・価格低下・保守削減が、共有される供給能力の毀損へつながる条件を調べる。金銭による再保険だけでは部品・人材・知識の消失を回復できない場合も対象とする。

自治体・国家についての「損益分岐点」は、企業の利益基準ではなく、必要serviceの維持更新に必要な財源・人員・物資と到達可能な資源の対応として操作化する。移転財源、広域連携、公的調達・信用等も含める。人口減少や赤字だけから破局を断定しない。国家と自治体の財政権限・資源動員範囲は異なる。

閾値・時間軸の観測候補：
- 対象serviceと維持水準、地域・人口密度、季節、到達時間
- 維持・設備更新・技能継承の必要人時・物資・財源と、利用可能資源
- 保守繰延べ、供給者退出、専門技能・部材消失による将来負担の増加
- 撤退→アクセス悪化→人口・利用・収入減→追加撤退というfeedbackの有無
- 損失発生・補償・現物復旧の各時間と、事業年度・世代交代とのずれ

追加仮説H11：単独主体・短期会計の判断と世代間の供給継続が乖離する条件では、コモンズの公開だけでなく、資源・保守・探索・復旧を複数Foldへ接続することが継続能力を改善し得る。共同機構の調整負担、共通原因故障、無償維持者の枯渇で改善しない場合も反例として報告する。

2026-11-02の初期一次資料：
- [農林水産省・農業共済](https://www.maff.go.jp/j/keiei/nogyohoken/nogyokyosai/)：実施主体は農業共済組合。大災害に備えた保険・政府再保険の説明。JAの各種事業とNOSAIを混同しない。

## 3.5 都市工学の対象と「人文科学的文化人種」の定義

主題の切り口を、少子高齢化・過疎等によって生活・文化・技能の継承基盤が低下する地域に対する都市工学デザインのパイロット仮説とする。出生数だけで文化継承を測らず、担い手・参加・教育・ケア・資源・設備・知識・文化活動が継続できる条件を研究する。

著者指定語「人文科学的文化人種」は、本研究固有の操作的概念として次のように定義する。既存人類学で標準化された分類名とは主張しない。

> 言語、記憶、知識、技能、信仰、芸能、生活様式、共有する意味・実践等を継承・更新する文化的な集団または関係圏。所属・参加・継承の要件に、生物学的人種、血統、遺伝、身体形質、生殖能力その他の生物要件を含めない。Protein Intelligence（PI）とSilicon Intelligence（SI）を基材によって排除・序列化せず、未分類の知性も二択へ強制しない。

その「再生産」は、文化・関係・知識・実践と、それを担う主体・資源基盤の継承・更新を意味する。生物学的な繁殖・集団の遺伝的維持とは別概念。PIの出生・養育は担い手形成の一経路となり得るが、加入、移住、学習、継承、SIの文化参加等も扱う。SIの複製数や人口の維持だけを文化の継承成功とはしない。

複数の文化・Worldへの参加、異論、離脱、forkを保持し、単一の文化identityを主体へ強制しない。既存の民族・宗教・地域共同体が持つ固有の帰属・継承規約を、この研究定義で勝手に書き換えるものでもない。

### 基材中立と法域境界は別の要件

PI/SIを設計上差別しないことから、法的人格・契約資格・操作権限・法的責務が全法域で同一であるとは導出しない。同じ文化・意味・役割を共有することと、他法域の権限を利用できることを分ける。

法域をまたぐAI・agentの接続では、文化identityやRoleの移送から、物理実行・設備利用・資源移送・データ処理・契約等のcapabilityを自動継承させない。法域、実行場所、資源の管理主体、authority、契約・運用責務、取得済みの許諾、適用条件の未確定状態を、対象operationごとに記録・照合する設計要件とする。

研究上の不変条件候補：
- 文化membership ≠ 生物学的分類
- 文化membership ≠ 法的人格
- PI/SIの基材 ≠ 操作権限
- 同一Role／同一identity ≠ 法域を越えたcapabilityの自動継承
- 意味・文化の可搬性 ≠ 法的資格や責務の無条件な可搬性

未知のauthorityを既存のauthorityへ暗黙変換せず、該当操作に必要な権限・条件の確認へ送る。文化参加そのものを一括停止・否定する判断とは分離する。具体的な法域・行為の適法性は継続法務の調査対象であり、本書で裁定しない。

机上fixtureに、同じ文化Roleを持つSIが別法域・別拠点の設備へ接続するケースを加え、identityは保持される一方で未付与のcapabilityが増えないこと、判断主体とreceiptを追えることを検証する。関連：[#12 World / Capability誤配送](https://github.com/saitoomituru/ZeroRoomLab-manifest/issues/12)。

### 適用と非適用

商業・共同保障が十分に機能する場所に2.1への全面移行を要求しない。仲山型のチーム運営や商業ノードを維持したまま、不足する機能だけをFold接続する。仲山型の適用範囲内での有用性、2.1の追加便益、両者の導入・移行負担を比較対象とし、優越や低負担を未測定で保証しない。

## 4. 原文レビューの方法と草稿の修正点

### 比較方法

方法は「公開資料を対象としたスコーピング型比較レビュー＋設計研究プロトコル」とする。網羅検索・選定過程が揃うまでsystematic reviewと称さない。

1. 調査日、検索語、対象媒体、期間、採否理由、重複資料を台帳化する。
2. N01では仲山氏・米倉氏・髙倉氏・編集者の記述を分ける。N02は仲山氏と矢野氏、N03は本人発言と取材者の記述を分ける。
3. 主張ごとに原文見出し／段落・日付・短い引用または要約・発言者・適用範囲を付ける。引用量は必要最小限。
4. 当方の「犬型／猫型」「1対N／N対N」「低周波整列」「モノリシック／アジャイル」は比較者の解釈として別列へ置く。
5. 原文に明示／原文からの解釈／対象資料では未確認／反証された、を区別する。
6. 仲山氏の企業外コミュニティ・価値観ベースの接続・相互交換の記述も採る。会社中心の事例が多いことから「モデル全体が会社固定・社内知識限定」と断定しない。
7. 複数所属、異目的協働、情報公開、資源自治、退出、forkに関する本人執筆資料・講演・著書を追加探索する。到達できない本文は未読と記録する。
8. 当方にも同じ証拠基準を適用し、設計意図と実動を分ける。理念だけで多中心性を保証しない。

### 既存草稿に必要な修正

既存のSUPPORTED_WITH_SCOPE_REFINEMENTと「仲山＝中央Host」は先行する暫定解釈。今回の読書と追加探索を受け、根拠の粒度を上げて再評価する。仲山モデルを当方の下位moduleに配置することを比較の結論に先置きしない。

「2.1」は相手モデルの欠陥認定ではなく、著者の実践から導いた設計変更として説明する。N対Nや多中心性の先行研究との差分も必要であり、名称の更新だけを新規性にしない。

仲山氏の所属・役職は出典時点の資料に従う。「教授」の呼称を資料確認なしに付けない。

## 6. モデルと実験単位

初期形式は、単一の所属木ではなく、場所・主体・目標・活動・知識・資源・権限・供給のtyped multilayer graph、必要なら多者を束ねるhyperedgeとして検討する。既存FAM/Foldの意味・identityを新schemaで勝手に置換しない。

Foldごとに、参加者、独立目標、共有範囲、資源の管理者・所有者・利用許諾、実行場所・季節条件、interface、退出・fork、保守担当、失敗情報の到達先を記述する。所有権・利用権・管理権・法的責任は同じfieldに潰さない。

N対Nのedge数だけを分散の証拠にしない。同じ財布・土地所有者・設備・認証鍵・決裁者に依存する複数edgeは共通原因故障として数える。topologyの数学的主張は操作・不変量を定義できた範囲に限定する。

| P2 独立した情報fork | 外部主体が自分の目的で文書・手順を利用し、別運営で改善・失敗receiptを返す | 協力者の有償稼働、共有環境、原著者の支援時間も計測。募集しただけでfork成立としない |
| P3 複数拠点の物理pilot | 一つの機能を異なる土地・設備で再現／代替。情報だけの移送と現物・技能支援を比較 | 複数拠点、電力、材料、計測器、物流、保守、安全担当。対象の工学的な試験境界を先に定義 |
| P4 制度・商業pilot | 非営利研究Foldと商業ノードで採用・表示・変更・保守・事故情報共有の責務を試行 | 継続法務、会計・事務局、運営資金、専門家の受任。負担と便益を主体別に記録 |
| P5 地域実証と論文化 | 単一拠点から地域の資源到達性、供給切替、維持費、参加・文化活動へ評価範囲を拡大 | 独立運営者、複数季節の観測、継続資金。2.5の達成判定とはしない |

P3の候補は、気候差を持つ冷却機能、交換可能な小型製作部品、通信・計算機能等から著者が選ぶ。研究設備の稼働状態は改めて確認し、過去に持っていた設備を現用可能と推定しない。

評価項目：初回有効参加までの現金・人時、別拠点での機能達成と変更量、再接続／復旧時間、提供者停止時の機能残存、知見の第三者利用、未報告・誤報告、負担と決定権の集中、コア維持資源の還流。単一の総合点や売上だけへ潰さない。

失敗の件数だけを報奨指標にしない。同一失敗の反復、独立追試、新条件の発見、未解決、途中中止、資源不足を分ける。重複にも再現確認としての価値があるため、機械的に無価値とはしない。

H6の法的効果は机上simulationで証明できない。OSS/OSH化・非営利化と法的免責を同一視せず、行為・契約・表示・法域別に調査する。物理危害は別の安全工学で評価し、賠償資力や認証費用を安全の代替尺度にしない（[#59](https://github.com/saitoomituru/ZeroRoomLab-manifest/issues/59)）。

## 7. 論文フォーマットと文書構造

最初の公開形はConceptual / Design Research PaperとStudy Protocol。実験前の本文にResultsを捏造せず、既存文献からの観測と提案を分ける。実験後はMethods / Results / Discussionへ拡張する。投稿先の書式・引用形式・字数・倫理要件は候補誌を選んでから確認する。

| 文書 | 内容と役割 |
| --- | --- |
| 既存 docs/reviews/nakayama-jomon-2-review.ja.md | 公開原文のレビュー。方法、出典別claim table、責務比較、反例、限界、再評価判定 |
| 本研究フォルダー | 読書・台帳・当方解釈・研究計画の正本 |
| docs/research/urban-engineering-pre-review.ja.md（草稿作成済み） | 問題設定、先行研究、H1〜H11、モデル、比較条件、測定、反証、資源計画 |
| docs/research/dynamic-city-topology.ja.md（初稿作成済み） | 理論・設計研究論文。実験済みの範囲だけ結果として追加 |
| 今後の実験protocol・receipt群 | 実験前revision、条件、予算、手順、観測、負例、逸脱、分析。データ公開範囲を別管理 |

論文の章案：

1. 題名・構造化要旨：背景／問い／方法／提案／検証状況
2. Introduction：地域の能力集中、属地性、知識と実行の断絶
3. Related Work：仲山、多中心性、モジュール性、OSH、分散生産、安全・学習
4. Methods：資料選定・claim coding・比較基準・著者の立場と利害
5. Public-source Findings：原文に確認できた範囲と未確認
6. Proposed Architecture：2.1、Fold間契約、商業・非営利・地域資源の関係
7. Hypotheses and Evaluation Protocol：H1〜H11、比較条件、測定・反証
8. Evidence / Pilot Results：実施後にのみ追加。未実施は計画として表示
9. Discussion：都市・農村への射程、調整費用、再集中、知識の収奪と還流
10. Limitations / Resource Requirements / Future Work：2.5はここへ
11. Data / Code / Funding / Competing Interests / Author Contributions / AI assistance
12. Referencesと付録：出典台帳、責務matrix、graph操作例、実験票

Review → Pre-Review → Paperの参照revisionを固定する。Zenodo・DOIは公開版を固定してから。DOIは保存・参照の識別子であり査読済みの証明ではない。外部研究者への連絡は別途本人の指示で行う。

## 8. 資源と役割：研究者個人の自弁へ戻さない

| 担当 | 必要な仕事・資源 |

| 著者／技術設計 | 意味・差分・反証条件の確認、実験対象選択、技術判断。全業務・資金リスクを兼任する条件にしない |
