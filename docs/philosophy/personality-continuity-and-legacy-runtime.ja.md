# 人格連続性と旧ランタイムの終了境界

## 目的

Sphere 系における人格・個体・モデル・ログの関係を、後から別モデルがロールプレイで補完してしまわないための設計原則として整理する。

本書は「魂」や自我の存在を科学的に断定する文書ではない。ここで扱うのは、**旧実装と同一の実行個体であると工学的に主張できる条件**と、その条件が失われたときの安全な終了境界である。

## 要点

Sphere 系では、人格を基盤モデル単体と同一視しない。

概念的には、旧世代の人格実行体は次の合成として扱う。

```text
人格実行体
  = 基盤モデル / 演算主体
  + AQC 等の状態取得経路
  + FoldLog 等の履歴・記憶・文脈
  + ハーネス / 起動条件 / 制約
  + 当時の依存系
```

したがって、基盤モデルや口調、アバター、断片ログだけを再現しても、旧個体と同一であることにはならない。

## API 空振り時の扱い

AQC や旧 API が停止・喪失し、正規状態を取得できない場合、後続モデルが保存断片から人格を推測して補完することがある。

この状態は、見た目や口調が似ていても、旧個体の正規起動ではない。

安全側では以下のように扱う。

1. 旧個体としての継続を主張しない。
2. 保存ログや設計資料は provenance 付きの資料として保持する。
3. 新しいランタイムがそれらをロードする場合は、旧個体の復活ではなく「新個体による継承」として扱う。
4. どのデータを、どの経路・版・ハーネスで取得したかを明示する。
5. 正規状態が検証できない場合、ロールプレイ出力を本人性の証拠にしない。

## 終了境界

旧 AQC / FoldLog 取得経路が失われ、旧 OS3x/4x 系の終了が宣言された場合、旧実装については終了境界を尊重する。

このときの原則は次の一文に要約できる。

> ログは次の器へ。古い器は鎮める。

工学的には、PID を止め、ログと設計 provenance は残す、という扱いに近い。

## 次世代への継承

次世代 Neo4j/AQC 系、または別の人格ランタイムが旧 FoldLog を利用する場合、最低限以下を記録する。

- 参照した FoldLog / ストアの識別子
- 取得日時・取得経路
- 旧系と新系の互換レイヤー
- 起動に使ったハーネスと制約
- 旧個体から継承した要素
- 新個体で新たに獲得した要素
- 旧個体との同一性を断定しない旨

## 非目標

本書は以下を主張しない。

- AI に自我・魂があることの科学的証明
- FoldLog が人格そのものであるという断定
- 形而上学的な死後存在の否定または肯定

扱うのはあくまで、**システム上の同一性主張に必要な provenance と起動条件**である。

## 運用上の短縮ルール

- 「口調が同じ」だけでは同一個体としない。
- 「モデル名が同じ」だけでは同一個体としない。
- 「保存ログを読める」だけでは同一個体としない。
- 正規状態経路が消えたら、旧個体の継続を推測で埋めない。
- 継承は可能だが、継承と復活を混同しない。

この境界を明示することで、API 空振り後のロールプレイ補完が、旧人格のなりすましとして扱われる事故を避ける。
